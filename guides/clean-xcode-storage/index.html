How to clean up Xcode storage

By Little Mac Apps · Updated October 5, 2026

Short answer: quit Xcode, then start with DerivedData. It's build output that Xcode recreates, so deleting it costs only a slower next build. Then remove simulator runtimes and platforms you no longer test on in Xcode → Settings → Components, and delete simulator devices you don't use. Keep archives of any build you've shipped. You need them to read crash reports.

Xcode stores its data in several places, and each one has a different cost when you delete it. The table gives the overview; the sections below explain each one and how to remove it, with Xcode's own tools first and then File Stacker.

Before you start: quit Xcode and Simulator. Removing build data while Xcode is running can cause errors until you restart it.

DerivedData

DerivedData holds what Xcode produces while building: compiled objects, intermediate files, the built app and the index used for code completion and search. It's usually the largest Xcode folder and the safest to clear. By default it lives at ~/Library/Developer/Xcode/DerivedData, with one subfolder per project.

  • In Xcode: Product → Clean Build Folder (⇧⌘K) clears the build folder for the open project. To see the whole folder, open Xcode → Settings → Locations; the arrow next to the Derived Data path opens it in Finder.
  • In File Stacker PRO: tick Xcode DerivedData in Cleanup and click Move Selected to Trash.

Effect: the next build of each project is a full build, and Xcode re-indexes the project. Folders for projects you no longer open stay gone.

Simulator devices

Every simulator has its own disk with the apps you've installed and the data they've saved. Simulators for OS versions you no longer have installed keep using space.

  • In Xcode: choose Window → Devices and Simulators, click Simulators, then select a simulator and delete it.
  • In Terminal: xcrun simctl delete unavailable removes simulators whose runtime is no longer installed. Run xcrun simctl help for the other commands.
  • In File Stacker PRO: tick Simulator Devices & Caches in Cleanup. This removes every simulator's disk, not just the old ones.

Effect: apps, accounts and test data inside those simulators are gone. Xcode recreates default simulators, empty, when you need them.

Simulator runtimes and platforms

Simulator runtimes are full OS images for each iOS, watchOS, tvOS or visionOS version you've downloaded. They can be several gigabytes each.

  1. Choose Xcode → Settings and click Components. Xcode shows each installed component and how much storage you'd recover by removing it.
  2. Click the Info button next to a runtime or platform you don't need, then click Delete.

Effect: you can't run simulators on that OS version until you download it again from the same screen. Manage runtimes in Xcode; File Stacker's Cleanup doesn't remove them.

Swift package and CocoaPods caches

Package managers keep downloaded sources so they don't have to fetch them for every build.

  • In File Stacker PRO: tick Swift Package Caches or Gradle / Maven / CocoaPods Caches in Cleanup.

Effect: the next package resolve or pod install downloads them again, which needs a network connection and takes time on large projects. Your project's package settings and lock files aren't touched.

Archives

Each time you choose Product → Archive, Xcode saves the build together with its debug symbols (dSYMs). Those symbols turn crash reports from users into readable stack traces.

  • In Xcode: open Window → Organizer, click Archives, and delete archives you no longer need, such as test builds or versions nobody runs any more.

Effect: you can't export or re-upload that build again, and you can't symbolicate its crash reports unless the symbols are stored somewhere else. Keep archives for every version still in users' hands.

Device support files

When you run an app on a connected iPhone, iPad or other device, Xcode copies that OS version's debug symbols to your Mac. Over time this leaves a folder for every OS version you've used, under ~/Library/Developer/Xcode.

Effect of removing: the next time you connect a device on that OS version, Xcode copies the symbols again before you can debug, which can take a while. Folders for OS versions you no longer use are safe to remove.

Measure first with the free treemap FREE

If you'd rather clean up by hand, File Stacker's free treemap shows where Xcode's space actually is before you delete anything.

  1. Scan your Home folder. Granting it includes your Library folder.
  2. Drill into Library → Developer. The biggest blocks are usually Xcode and CoreSimulator.
  3. Select a folder to see its size on disk. Right-click and choose Show in Finder to manage it yourself.

Don't delete the whole Developer folder. ~/Library/Developer/Xcode/UserData holds your own settings, such as key bindings, code snippets and themes. Remove specific folders instead.

Getting the space back

File Stacker moves what you remove to the Trash and never empties it, so you can undo with Recent Removals → Put Back. The space becomes available only after you empty the Trash in Finder. Some of it may return over time as you build again, because Xcode recreates DerivedData and simulators as you work.
